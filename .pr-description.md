# Add MiMo-V2.5-ASR — Xiaomi multilingual ASR (zh/en/dialects/code-switch)

## Summary

Adds a new STT engine `STT.mimo()` powered by Xiaomi's
[MiMo-V2.5-ASR](https://github.com/XiaomiMiMo/MiMo-V2.5-ASR). MiMo is a
SOTA end-to-end ASR model designed for robust transcription across
Mandarin, English, multiple Chinese dialects, code-switched speech, song
lyrics, knowledge-intensive content, noisy environments, and
multi-speaker conversations. The Apple Silicon MLX conversion lives at
[`mlx-community/MiMo-V2.5-ASR-MLX`](https://huggingface.co/mlx-community/MiMo-V2.5-ASR-MLX)
(int4 affine, 4.5 GB) and runs end-to-end at **~1.4 s warm on M2 Pro for
2-second utterances**.

The Python reference port is at
[`ailuntx/mlx-audio@feat/mimo-v25-asr`](https://github.com/ailuntx/mlx-audio/tree/feat/mimo-v25-asr).
The model card itself notes that Swift integration was a TODO ("the
usage section will be simplified once MiMo lands in upstream mlx-audio
and mlx-audio-swift"). This PR delivers that Swift integration.

## What's new

```swift
let mimo = STT.mimo()
try await mimo.load()
let result = try await mimo.transcribe(audioURL)            // auto language
let zh     = try await mimo.transcribe(audioURL, language: .chinese)
let en     = try await mimo.transcribe(audioURL, language: .english)
```

`STT.mimo(localDirectory:)` is also available for offline use (e.g.
weights cached by LM Studio at `~/.lmstudio/models/`).

## Architecture

MiMo-V2.5-ASR is a multimodal LLM, not a Whisper-style encoder-decoder.
The pipeline:

```
audio @24kHz
  → log-mel (128, T)              [n_fft=960, hop=240, HTK scale, natural log]
  → MiMo audio tokenizer (Codec/MiMoAudioTokenizer/)
      conv1 → conv2 (stride 2)
      32× transformer (full attention, RoPE base 10000)
      skip connection from layer 3
      LayerNorm → optional 2× downsample → LayerNorm
      RVQ encode (first 8 of 20 codebooks)
  → 8-channel audio codes (8, T_tokens)
  → prompt assembly (text + speech rows, 6 segments)
  → MiMo LLM (STT/MiMo/Layers/MiMoAudioMLX.swift)
      8 per-channel speech embeddings, summed per group
      input local transformer (6 L, full attention)
      speech_group_downcast: 1024*4 → 4096
      36-layer Qwen2 backbone (text + fused speech embeds)
      hidden_states_downcast: 4096 → 1024
      delay-pattern local decoder (16 L, causal, 11 micro-steps)
      8 per-channel speech LM heads + text lm_head
  → autoregressive generation (group_size=4 text tokens then conditional
                                8×4 speech tokens via delay-pattern)
  → text token detokenization
```

## Implementation choices

- **Reuses the established mlx-swift-audio Qwen2 implementation** from
  `TTS/Shared/CosyVoiceQwen2Backbone.swift`, **extended with a
  caller-selected `MLXFast.ScaledDotProductAttentionMaskMode`** so the
  MiMo input-local transformer (4-token groups, full attention) can run
  with `.none` while CosyVoice's existing `L > 1 ? .causal : .none`
  remains the default. CosyVoice callsites are unchanged.
- **Sibling `MiMoLocalQwen2` class** without `embed_tokens` for the two
  local transformers (which consume `inputEmbeddings:` only). The
  safetensors index intentionally omits `input_local_transformer.embed_tokens.*`
  and `local_transformer.embed_tokens.*`; `verify: [.noUnusedKeys]` is
  happy because the class never declares those properties.
- **New `melFiltersHTKNoNorm`** helper (mimo uses HTK mel scale with no
  Slaney area normalization, where `S3TokenizerUtils.melFilters` is
  Slaney). The existing `stft` and `hanningWindow` helpers are reused.
- **Weight loading** mirrors `FunASRModel`: merge all safetensors shards
  first, run a tuple-returning `MLXNN.quantize` filter on the merged
  `.scales` presence (the configured int4/group_size=64/affine is read
  from `config.json`), then `update(parameters: ModuleParameters.unflattened(...),
  verify: [.noUnusedKeys])`.
- **Sanitizer drops `position_embedding.inv_freq`** (recomputed on
  demand from `rope_theta`) so strict loading succeeds. `k_proj` is
  declared with `bias: false` to match the safetensors layout (no
  zero-injection needed).
- **English instruction template pinned** to `"Please transcribe this
  audio file"` (the first ASR_EN_TEMPLATES entry). The Python reference
  uses `random.choice(...)` which breaks parity fixtures; deterministic
  pinning makes goldens stable. Chinese/auto paths use the same
  hardcoded token IDs as the reference.

## Spec & review

This change was developed against a written spec
(`docs/mimo-mlx-swift-spec.md` in [OpenTTS contributors' fork](#))
which went through two adversarial review passes by an independent
agent. All 11 review gates are GO after revision 3:

- ✅ Sibling-class `MiMoLocalQwen2` with explicit registered leaf keys
- ✅ `MaskMode` plumbing (preserves CosyVoice's L>1 default)
- ✅ `melFiltersHTKNoNorm` matches Python `mel_filters(..., norm=None, mel_scale="htk")`
- ✅ `quantize(..., filter:)` named-arg form on `.scales` presence
- ✅ `verify: [.noUnusedKeys]` after sanitizer drops `position_embedding.inv_freq`
- ✅ `ModuleParameters.unflattened` for dot-path keys
- ✅ `MLX.loadArrays(url:)` returning `[String: MLXArray]`
- ✅ `B == 1` enforced via runtime guard at public API
- ✅ English template pinned (deterministic)
- ✅ Tokenizer spike: byte-identical encode against Python AutoTokenizer
- ✅ Weight-load spike: real safetensor backbone layer 0 loads + quantizes + forward

⚠️ **`swift test` quirk:** the test target requires `mlx.metallib` next
to the xctest binary — SwiftPM doesn't bundle Cmlx's metal kernels.
Workaround documented in this PR's README diff:

```bash
cp ~/Library/.../mlx/lib/mlx.metallib \
   .build/arm64-apple-macosx/debug/mlx-audioPackageTests.xctest/Contents/MacOS/
swift test --filter Mimo
```

Running tests under Xcode includes the Metal build phase automatically;
this PR doesn't change that.

## Known limitations (v1)

- B == 1 only. Multi-utterance batching is a future change (Python
  reference also branches on `next_text_token[0]`).
- No streaming. Whole-clip transcription only, matching the reference.
- No translation. MiMo can translate but we ship transcription only.
- No selectable precision variants. The one available HF artifact is
  int4; q8/fp16 will be added if/when artifact-backed repository IDs
  exist.
- iOS likely works (mlx-swift-audio's Package.swift platform = iOS
  18.4+) but is not promised in v1.
